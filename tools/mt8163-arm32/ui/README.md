# LibreEcho-UI image integration

The web application remains in the separate `LibreEcho-UI` repository. This
directory owns the image-side build and packaging contract.

`build_ui_bundle.sh` accepts an explicit UI checkout and stages static ARM32
daemons, web assets, init scripts, and the default configuration. The image
records the UI commit, source diff identity, and a deterministic file manifest.

The production bundle requires `LIBREECHO_UI_MBEDTLS_ROOT`, the pinned static
ARM32 mbedTLS prefix built by `tools/mt8163-arm32/mbedtls` (see that directory's
`README.md`). The builder passes its include path and the absolute path of each
verified archive, derived from the verified prefix rather than from a
caller-supplied archive list, as the `WEB_TLS_LIBS`/`RADIOD_TLS_LIBS` link
inputs to both `libreecho-web` and
`libreecho-radiod`, then runs `ui/verify_ui_tls.sh` against the compiled and the
stripped, staged binaries. The verifier accepts only the pinned identity: the
prefix version must equal `mbedtls/SOURCE.lock`, and its `mbedtls-source.json`
provenance record must match the lock, the SHA-256 of each archive that is about
to be linked, and the recorded include-tree digest of the headers the build
compiles against. A bundle that compiled `src/tls_stub.c`
(`LE_TLS_AVAILABLE=0`), lost the mbedTLS link, linked a stale or substituted
mbedTLS, or stopped being static ARM32 fails the build instead of shipping an
HTTPS toggle that cannot listen on 8443.

The daemons are packaged as default boot services after the recovery control
plane has configured loopback. They do not replace the existing kernel or
initramfs control plane:

- `networkd` attaches to the existing `wpa_supplicant` control socket.
- `audiod` uses the existing ALSA device and mixer controls.
- `micd` owns on-demand microphone capture and starts with capture idle.
- `ledd` uses the existing LED sysfs/I2C controls.
- `libreecho-web` exposes those adapters over the local HTTP API.

## Home Assistant satellite (0.14)

The shipped satellite is `libreecho-esphomed` with
`init/libreecho-esphomed.init`: TCP 6053, `_esphomelib._tcp`, selected only by
integration bit 1. There is no satellite protocol selector and no shipped
Wyoming satellite binary, init or advertisement. The Custom voice pipeline
retains `libreecho-sttd-wyoming` and `libreecho-ttsd-wyoming` as musl clients;
the saved Local/Custom selection is not rewritten when HA is enabled or disabled.

The UI Makefile must accept the following production release interface and pass
it through its recursive `release` build:

```sh
ESPHOMED_NOISE=1
ESPHOMED_TLS_LIBS="<prefix>/lib/libmbedtls.a <prefix>/lib/libmbedx509.a <prefix>/lib/libmbedcrypto.a"
```

The builder exports `CPPFLAGS=-I<prefix>/include` as for web/radio TLS. It runs
`verify_ui_tls.sh --noise-prefix <prefix>` before building: effective preprocessing
of `mbedtls/build_info.h` must enable ECDH, Curve25519, ChaChaPoly, SHA-256 and
MD/HMAC. Prefix provenance and all archive/header digests remain mandatory; a
caller-supplied alternate library list is not used.

`config/esphome.service` is a reference schema packaged outside the runtime
Avahi service directory, not a static advertisement. MAC placeholders are
permitted; a device MAC or Noise/API key is not. The runtime supervisor receives
esphomed's readiness-bound discovery lease and owns stale service withdrawal.
The image builder rejects unexpected bundle members, while the independent
verifier also rejects obsolete Wyoming satellite entries/advertisements.
`watchdogd` must be compiled, validated, staged and present in both image
inventories; compiling an unshipped supervisor is not closure.

Boot and setup reconciliation stop conflicting satellite/local owners before
starting the selected graph. HA health requires a live esphomed init status,
its exact executable PID and a 6053 listening socket inode owned by that PID;
another listener or a stale pidfile cannot confirm an OTA slot. Custom STT/TTS
clients do not require local model payloads. These are host/source contracts,
not image-build, Home Assistant enrollment or audio/hardware acceptance.

Set `LIBREECHO_WEB_USERS_FILE` to a private file generated by
`LibreEcho-UI/tools/create-user.sh` when building a development image. The
bundle installs it as `/etc/libreecho/users` with mode `0600`; the boot service
then enables local-user authentication automatically. Passwords are never
stored in this repository.

The image init script starts `logd`, `networkd`, `audiod`, `micd`, `ledd`, and
`web` in that order (with any additional integration daemons between the
hardware adapters and web). Each service is idempotent and can still be
restarted through its init script for development.
